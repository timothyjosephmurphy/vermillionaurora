# Art book galleries

The new `/book-galleries/` collection is separate from `collections.home` and `collections.gallery`. It contains the labeled sections and nested collections of TJ Murphy's *Watercolor Landscapes* and *Watercolor Portraits*. Existing carousels and original stock identities are unchanged.

## Sources and extraction

`catalog/book-galleries.json` records PDF URLs and SHA-256 digests, page numbers, embedded image references, pixel crops, captions, and native dimensions. Extraction reuses the PDFs and the PyMuPDF approach from the October 1 print-source audit. Raster section headings were transcribed from rendered pages. Native images are extracted with their PDF clipping and transparency; complete images behind facing-page spreads are recovered once. Identical image bytes across books share assets and one new book artwork identity. The book artwork identities never create a second purchasable original.

Original dimensions without a unit remain book measurements, not assumed inches. Ambiguous or absent names use section/page references; a series measurement is labeled as such. Author biographies and lettering are not turned into saleable prints.

## Media

Use the existing `images` R2 bucket, under `images/book-galleries/v1/`. Gallery previews are WebP at no more than 1000 pixels on their longer side; full images retain their extracted pixel count. Print sheets live in `images/book-galleries/v1/prints/` with SHA-256 filenames. All use the existing media domain. Nothing changes the commission-reference bucket.

`prepare-book-galleries.yml` reproduces extraction against pinned source hashes, checks output hashes, uploads only manifest-listed objects through a short-lived authenticated Worker, verifies each object's public bytes, and removes the uploader. The uploader cannot list/read/delete bucket content or write outside its exact manifest. It refuses a conflicting existing object. Uploaded assets remain after cleanup.

## Prints

The existing 300-PPI edition layout, no enlargement, white trimming margin, proportional 100%/75%/50% choices, supplier minimum sizes, and existing retail pricing rules apply. Only supported sizes receive verified supplier prices and are enabled. Small images remain gallery-only. Resolution screening is not a physical color proof. No sample orders, payments, labels, or customer emails are generated by preparation.

Book print records live in `catalog/book-prints.json`; `print-config.mjs` combines them with the existing print configuration. This keeps ongoing original-gallery print updates independent. The deployed backend and website must have matching generated print catalogs before the new purchase flow is considered complete.

## Reproduce

1. `node scripts/download-book-sources.mjs .cache/book-sources`
2. `python scripts/extract-book-galleries.py .cache/book-sources .cache/book-work`
3. `python scripts/prepare-book-catalog.py .cache/book-work .cache/book-sources` (review metadata changes before publishing)
4. `node scripts/prepare-book-print-assets.mjs .cache/book-work` (resets these new print entries to unpriced/disabled; reapply verified quotes)
5. `node scripts/apply-book-print-prices.mjs` reapplies the verified snapshot in `catalog/book-print-quotes.json`; regenerate both checkout catalogs afterward. Refresh that snapshot using the read-only quote workflow when prices change.

## Corrected display photos

Some book images are phone photos of a painting on a desk. `catalog/book-photo-corrections.json` lists perspective corrections for them: the four paper corners in the native PDF image, the upright size, and the crop to the paper (white margin kept, no background). `python scripts/book_photo_corrections.py .cache/book-sources OUT` reproduces the committed JPEG (quality 96, 4:4:4) and WebP (≤1000 px, quality 85) with Pillow 12.3.0. They get new immutable keys (`<key>-paper.jpg/.webp`); the original extracted objects stay in R2 untouched. `prepare-book-catalog.py` points the artwork's `masterUrl`/`previewUrl` and product image (with width/height) at the corrected files, while `masterSha256`/`widthPx`/`heightPx` keep describing the extracted book image. Corrected photos are display-only: print preparation refuses a corrected artwork that is a print candidate.

Upload: `upload-book-photo-corrections.yml` runs on a push to `codex/book-photo-*` whose commit message includes `[upload-book-photos]` (or by dispatch). It deploys the same bounded uploader limited to `scripts/book-photo-corrections/uploads.json`, verifies the public bytes, and removes the uploader. Upload before the catalog change reaches `release`.
