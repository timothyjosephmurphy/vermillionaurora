# Shared checkout for original paintings

The product page script calls the `vermillion-commissions` Worker. One SQLite-backed Durable Object per painting holds the reservation, PayPal order, and sold state. The Worker reads its fixed-price catalog from `cloudflare/checkout-catalog.mjs`, generated with `node payments/build-checkout-catalog.mjs`. That generator rejects a product title or displayed price that differs from inventory and excludes sold/not-for-sale works and paintings with a separate hosted PayPal link. Rebuild the catalog when inventory or product prices change.

## Enablement

Checkout ships **disabled** (`PAYPAL_CHECKOUT_ENABLED=false` in `cloudflare/wrangler.jsonc`). Product pages retain their inquiry links while it is disabled. To go live:

1. Set encrypted `PAYPAL_CLIENT_ID` and `PAYPAL_CLIENT_SECRET` on the **Cloudflare `vermillion-commissions` Worker**, using the same live Business REST app. GitHub Actions secrets do not supply these to the Worker. Keep `GITHUB_TOKEN` (Contents read/write on this repository) and `PAYPAL_MERCHANT_ID` configured there too. Never commit secrets.
2. In the PayPal Developer Dashboard for that live app, subscribe `https://vermillion-commissions.timothyjosephmurphy.workers.dev/checkout/webhook` to `PAYMENT.CAPTURE.COMPLETED`. Set the resulting webhook ID as encrypted Worker secret `PAYPAL_WEBHOOK_ID`. This is separate from the legacy account-wide IPN listener at `/paypal-ipn`.
3. Create a Shippo account and add its API token as encrypted Worker secret `SHIPPO_TOKEN`. Add `SHIP_FROM_STREET` as an encrypted secret containing the physical street address for shipments from Seattle, WA 98122. The address is used in Shippo rate requests and should not be committed. Create a Stripe account with Stripe Tax configured for jurisdictions where you are registered to collect; add its secret API key as encrypted Worker secret `STRIPE_SECRET_KEY`. Stripe Tax can calculate tax for payments processed outside Stripe, but you must configure your tax registrations and reporting. Checkout is US-only until international shipping/tax is designed.
4. For a quote, the buyer enters a US shipping address on the product page. Shippo returns live carrier rates and the site selects the least expensive valid USD rate. Stripe Tax calculates tax on the painting plus that shipping amount. The complete painting + shipping + tax total is shown before PayPal. PayPal receives the provided shipping address and the fixed total. After a confirmed capture, an alarm retries the Stripe Tax transaction record and GitHub inventory update. No shipping label is purchased automatically.
5. The packaging assumptions require a physical check before live checkout: paintings whose longer side exceeds 12 inches are rolled in a 4 × 4 inch tube as long as the shorter painting side (rounded up); smaller paintings use a flat 2-inch-thick package with 2 inches added to each paper dimension. Both are quoted at **2 lb**. Paul Murphy's 40 available paintings have been recorded as **9 × 12 inches** as supplied by the artist. Correct package dimensions and weight in `payments/build-checkout-catalog.mjs` if the actual packed item differs. A lower quoted rate may not include the insurance needed for a high-value original; verify your shipping service and coverage before enabling live checkout.
6. Test the sandbox flow with PayPal Sandbox credentials, a Shippo test token, and a Stripe test key in a separate test deployment, including two simultaneous buyers, a cancellation, completed capture, webhook delivery, and the test tax transaction. Verify the GitHub inventory update separately with its local mocked test, then check it during a controlled live purchase. Never change the production Worker's mode to sandbox while live buttons are enabled.
7. Set `PAYPAL_CHECKOUT_ENABLED=true` in the Wrangler configuration, deploy the Worker and website, and verify one controlled live purchase before promoting the remaining products.

When a PayPal capture is completed, the Durable Object marks the original sold immediately. An alarm retries the GitHub inventory/page commit until it succeeds; product buttons consult the object directly while the static site catches up. A create order failure releases its hold. An abandoned hold expires after 20 minutes. An uncertain capture remains locked until a retry or a verified PayPal webhook reconciles it. Never manually clear a `capturing` lock without checking PayPal Activity.

The old API-created reusable payment links must remain unpublished; they cannot enforce a stock limit. Retire them through PayPal API once the new flow is live. The separate Warsaw stock-limited link remains in `payments/paypal-links.json` and uses its current flow.

## Isolated sandbox deployment

The separate `vermillion-checkout-sandbox` Worker uses `cloudflare/wrangler.sandbox.jsonc` and `cloudflare/checkout-sandbox.mjs`. It exposes `/checkout/health` and `/checkout/test`, and has its own SQLite Durable Objects. It refuses to run if a `GITHUB_TOKEN` is set. Sandbox captures update only its local stock state and a Stripe **test** tax transaction; they never commit to the live inventory. The production Worker remains in live mode with shared checkout disabled.

Run **Deploy isolated checkout sandbox** from GitHub Actions on the repository's main branch. It checks out the draft PR branch, runs the checkout tests, and deploys only the named sandbox Worker using the repository secret `CLOUDFLARE_API_TOKEN`. The token should have Editor access only to this Worker.

After the first deployment, set these encrypted secrets on **the sandbox Worker**: `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` (sandbox REST app); `PAYPAL_MERCHANT_ID` (sandbox business account); `SHIPPO_TOKEN` (test token); `STRIPE_SECRET_KEY` (test key); `SHIP_FROM_STREET` (shipping origin); and `PAYPAL_WEBHOOK_ID` (sandbox app webhook for `https://vermillion-checkout-sandbox.timothyjosephmurphy.workers.dev/checkout/webhook`, subscribed to `PAYMENT.CAPTURE.COMPLETED`). Never copy live provider keys or `GITHUB_TOKEN` into this Worker.

Once those settings are present, change `PAYPAL_CHECKOUT_ENABLED` in **the sandbox Wrangler config only** to `true`, then deploy it again. Use `https://vermillion-checkout-sandbox.timothyjosephmurphy.workers.dev/checkout/test` with sandbox buyer credentials. The test page does not appear on the production site. Validate quotes, cancellation, capture, stock status, and webhook delivery. A sandbox capture is not a real purchase and does not mark a painting sold on the site.
